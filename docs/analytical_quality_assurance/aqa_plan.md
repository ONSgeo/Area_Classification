# Analytical quality assurance plan

The current steps which have been implemented for quality assurance:
| Step |	Explanation |	
| -------- |   ---------- |  
| Code Review | Code has been written using the version control abilities of GitHub and when committing updates, these have been peer reviewed but colleagues before approving to merge into the main|	
| Testing | Unit tests and integration tests have been written to test functions are working as expected when ran on mock data |	
| Manual validation | Input data tables, intermediate outputs and final outputs have been manually checked to ensure quality and the pipeline is running as intended |	
| Validation checks | At stages of the process where mathematical actions per performed validation checks have been completed to check the outputs are what would be expected. |	
| Documentation | Documentation has been written alongside this code and DocStrings included to enable reproducibility. Documentation has also been QA'd. |	
| Change Management | Any future changes to the code will be QA'd in the same way as the original code with reviews, testing, validation checks, and documentation added where needed.  |	
| Continuous Improvement | Feedback can be submitted to the repo as issues and will be reviewed by the ONS Geo team. |

This analytical quality assurance (AQA) plan outlines [our implementation of the
Aqua Book][aqua-book] for this project. [Further resources related to the Aqua Book
are also available on GOV.UK][aqua-book-resources].

This is a living document, and should be updated and/or modified as necessary. For
example if new tasks not listed here become relevant to project success, please add
them to this plan.

[aqua-book]: https://www.gov.uk/government/publications/the-aqua-book-guidance-on-producing-quality-analysis-for-government
[aqua-book-resources]: https://www.gov.uk/government/collections/aqua-book-resources
